# Reproduction

Use Python 3.11+ with its standard library; the four scripts have fixed seeds where randomness is used. Extract the archive in a fresh directory. Do not run Python with `-O`, because the verifiers use assertions. Each program writes its named JSON output beside its source.

```sh
sha256sum -c MANIFEST.sha256
python verify_counts.py
python replay_counts_dp.py
python verify_switches.py
python verify_tours.py
```

Expected terminal indicators: `EXHAUSTIVE_COUNT_PASS`, `INDEPENDENT_DP_PASS`, `SWITCH_ROUNDTRIP_PASS`, `LAST_EXIT_AND_BEST_PASS`. The replay depends on the `counts.json` generated by the first script. The 242 replayed vectors and 76 additional vectors are sorted degree sequences; the other counts are labelled instances or local tests as indicated. Counts in the JSON records use exact integers. Check `ACCEPTANCE.json` for the archived environment and status. For a clean rerun, compare generated JSON data to the archived JSON, not build timestamps.

Lean: use Lean 4.28.0 with mathlib commit `8f9d9cff6bd728b17a24e163c9402775d9e6a365`. From that checkout run `lake env lean /absolute/path/to/DegreeCountCore.lean`. Only selected parity and algebraic kernels are formalized; the full graph and entropy theorems have analytical proofs. Earlier source and logs are retained as evidence. See the accepted source's compile exit status and axiom reports in `lean_evidence`.

PDF: `pdflatex -interaction=nonstopmode -halt-on-error manuscript.tex` twice. Exact PDF bytes across installations are not promised. Use the archive's SHA-256 manifest for the actual publication snapshot.
